# Crypto 管理與歷史

Crypto 歷史頁為日常管理入口。平台持倉、借貸、幣種價格設定及資金紀錄在受保護的管理 API 儲存，修改採用版本檢查、原子寫入及完整前後審計。

- 遷移先核對 Google Sheet 全部 Crypto 年度分頁，保留原表值、來源校驗碼及現有鎖定月結。原表保留為備份。
- 平台持倉是唯一幣數來源，以十進位精確加總（包含可用、質押、抵押及質押收益），每次儲存變動均與資產大表在同一次交易內同步；每日價格更新後亦再核對。借貸獨立扣減淨資產；Futu 的加密貨幣獨立管理。
- 資產大表保存持倉版本及數量校驗碼，管理中心顯示同步結果。若需要重新核對，可用「核對並同步」只修復資產大表，保留既有價格、平台持倉及歷史；並檢查資料版本、資產校驗碼與重試操作 ID。重複 Crypto 資產只封存，不刪除歷史；幣別或帳戶衝突會停止自動寫入。
- Crypto 本金為管理紀錄的累計本金。舊資金流水保留，但不再重複加入此累計數字。新資金紀錄亦同步供投資組合期間回報使用。
- 每日市場價格更新沿用原排程。手動價格不作市場代號搜尋，未确认價格保留空白；報價有效期沿用全系統 Crypto 的 24 小時設定。
- 月結改為純手動：在「月結歷史」按「執行當月月結」，每月任何一日均可建立當月快照，保存實際執行日期、平台持倉幣數與狀態、有效價格、借貸、本金及提取紀錄。平台持倉是幣數唯一來源，資產大表只供讀取價格。已鎖定月份不覆蓋；缺價或缺匯率只保存草稿，補齊後須再次手動執行。
- 每日價格／匯率更新、持倉同步及每日投資組合快照保留；每日主排程和救援排程均不再觸發 Crypto 月結，沒有獨立的月初月結排程。
- 新月結以實際持倉減借貸估值，提取／消費獨立列示。舊月結保留原表口徑；新月份同比使用上一個月的淨資產作同口徑比較。
- 管理資料與來源備份可匯出 JSON。Firestore 規則限制舊頁面直接更改 Crypto 數量、本金和資金流水；市場價格更新仍可正常寫入。

正式環境使用 `/api/health?mode=crypto-management`，不新增 Vercel Function。候選規則須通過 Firebase 編譯驗證，並單獨發布，Git 推送不會自動發布 Firestore 規則。

交付驗證包括型別／正式建置、回歸測試、獨立環境的新增修改移除操作、桌面與 390px 手機版面，以及遷移後後端與頁面回讀。2026-10-30 起 Crypto 月結只由手動操作觸發。

2026-10-12 已核對並同步 15 個幣種，精確數量全部一致；既有價格、成本、76 筆交易、56 個歷史月結及其他帳戶均經前後比較確認未變。同步功能與缺價時仍顯示幣數的版本已部署（`279e4a59`），269 項回歸測試、型別與正式建置通過。

直接開啟 `/assets` 曾被靜態資源路由攔截。`vercel.json` 已加入明確的頁面 rewrite；由於其 Git 部署取不到提交資料，正式環境另外發布了相同的 Vercel project routing rule：`Assets page document`，exact match `/assets` → `/index.html`，route ID `7eb8cbea-8334-426b-b112-e9c25fdd4ea1`，live version `a59377f4-ae22-4f9e-9bdf-96e3f8c5fa22`。此規則不匹配 `/assets/*`；正式網址的 `/assets`（包括 query）、Crypto 頁、入口程式與樣式均已回讀驗證。後續部署不需重建此規則；若移除它，須先確認部署本身的 rewrite 已正常生效。
